# Workflows

## Local workbench (try it in a browser)

A [Testbench workbench](https://packages.tools/testbench) app lives in `workbench/` so you can click
through the package without wiring it into a host project:

```bash
composer install
composer serve
```

`composer serve` runs `composer build` first — discovers the package provider, creates a SQLite
database, runs the migrations, and seeds demo data — then boots at `http://127.0.0.1:8000`:

- **`/`** — the login page rendering `<x-sso />`
- **`/dev/login`** — log in as the seeded admin (`admin@example.com` / `password`)
- **`/admin/settings/sso`** — the Livewire + Flux admin UI

For the admin UI to render with the real **Flux** styles (instead of the Tailwind CDN fallback),
compile the demo stylesheet once:

```bash
npm install
npm run build:css
```

> Seeded providers use placeholder credentials, so clicking a button reaches the real IdP and fails at
> *their* end. Edit a provider with real `client_id` / `client_secret` to complete a full OAuth round
> trip. Run `composer build` any time to reset the demo database.

### Workbench gotchas

- **`composer serve` re-discovers the package provider** (via `composer prepare`). Without it, a stale
  Testbench discovery cache boots the app without `ConfigSsoServiceProvider`, and every package route
  500s ("Unable to locate a class or view for component [sso]").
- **Do not add a `users` migration** in `workbench/database/migrations` — Testbench already loads its
  own `testbench_create_users_table`, and a second one collides.
- **The `testbench.yaml` `build:` list only understands recipe tokens** (`create-sqlite-db`, …), not
  arbitrary `migrate:fresh --seed`. Migrate + seed run explicitly in the composer `build` script, and
  seeding needs the fully-qualified `--class='Workbench\Database\Seeders\DatabaseSeeder'`.
- **The compiled CSS** (`workbench/public/build/`) and `package-lock.json` are generated artifacts and
  are gitignored.

## Contribution conventions

- Every change traces to a GitHub issue; reference it in commits/PRs.
- **Conventional commits.** `CHANGELOG.md` is auto-generated by the release workflow — don't hand-edit it.
- Git tags use **no `v` prefix** (e.g. `1.0.0`).
- Keep the package free of consuming-app coupling — see
  [decoupling rules](../01-architecture/02-patterns.md).
- Run the quality gates before pushing:

```bash
composer format    # Laravel Pint
composer analyse   # PHPStan / Larastan level 5
composer test      # Pest
```
